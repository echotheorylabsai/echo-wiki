# Finish in the destination repository

1. **Configure.** Read `_meta/wiki.config.yaml` and its schema. Set the chosen name, description, domains and default workspace; keep the standard layout. Create configured article directories and the chosen workspace as real directories with `.gitkeep`. Preserve existing configuration on resumed onboarding. Use the normal writer lock around configuration, directory and instruction changes; release it before invoking other skills.
2. **Link Codex and integrate instructions.** Ensure all nine Echo skills have relative directory links at `.agents/skills/<name>` pointing to `../../.claude/skills/<name>`. Fresh bootstrap creates them. For resumed/older instances, run `ruby <upstream>/.claude/skills/onboard/scripts/link-codex-skills.rb --check <destination>` and then `--apply`; use the complete current upstream checkout if the installed helper is missing. This preserves existing skill definitions and adds missing links only; conflicting names and symlinked parent directories block writes. The helper acquires/releases its own writer lock, so run it before taking a lock for instruction edits. Never replace unrelated Codex skills or duplicate the canonical definitions. Review every copied or preserved agent instruction file. In existing `AGENTS.md`, `CLAUDE.md`, or `GEMINI.md`, merge a short Echo Wiki section linking to the config, schema, and `.claude/skills/`, noting that Codex discovers the same definitions through `.agents/skills/`. Preserve existing project rules. Scope Echo Wiki formatting and source rules to managed `raw/` and `wiki/` content, never to the repository's application code or original documents. Include source-only KB changes through ingest/compile, append-only raw sources, actor workspace ownership, and validation/reindex commands. For other agents, use their actual project instruction mechanism or explicitly load the skill file; do not claim automatic discovery without checking. Add only missing rules from [the instance ignore template](../assets/instance.gitignore); do not replace existing rules. Check that original artifacts retain their Git visibility and intended runtime/knowledge files are visible to Git; resolve conflicting ignore rules before reporting commit-ready. Never copy `.env`.
3. **Hooks.** Inspect `git config --get core.hooksPath` and `git rev-parse --git-path hooks`. For an ordinary clone with no hook manager or existing hook, link `hooks/pre-commit.sh` as pre-commit and `hooks/token-count.sh` as post-commit, without overwriting existing hooks. For a linked worktree, existing hooks or a hook manager, preserve them and propose compatible integration; changing shared/global hooks requires user authorization. If integration remains unresolved, report it as pending and use manual validation. Reconcile agent instructions with the actual hook status; do not claim automatic validation is enabled when it is pending.
4. **Validate setup.** Run `./hooks/reindex.sh`, then `./hooks/validate.sh --all`. Confirm the configured workspace and all required paths exist. Check every Codex link resolves to the matching canonical skill. Confirm all nine skills appear in Codex’s skill picker/list from the destination repository; restart the session if necessary. If Codex is unavailable, report “links verified; native Codex discovery pending” rather than claiming discovery succeeded. Review the diff and untracked files against the plan. On an empty wiki, `OK: 0 files validated` confirms structure only.
5. **First source.** Ask for one real source if none was selected. Follow the installed ingest skill, then compile, checking both outputs. The workflows acquire writer locks: release an ingest-owned lock after its raw write/log step before invoking compile as a separate operation; do not nest lock acquisition. Preserve the raw snapshot after ingestion. If extraction is unavailable, report the exact export/tool needed and stop this step.
6. **Prove usefulness.** Run a relevant query; inspect its article citations and at least one factual claim against the raw source. Clearly separate supported facts, plans and inferences. Fix new output errors through the appropriate workflow and rerun validation. If no source is available, report “setup validated; first-source verification pending.” Do not fabricate demo knowledge and call it customer evidence.
7. **Handoff.** Summarize configured domains/workspace, files changed, preserved artifacts, hook status, source/answer checks and remaining action items. Explain the invocation syntax: Claude Code uses `/name`; Codex uses the skill picker or `$name` where supported. The examples below use Claude syntax: `/ingest` new evidence; `/query` answers; `/context <area>` working context; `/index` workspace changes; `/maintain` a manual health review. Open `wiki/` in Obsidian. Existing-source replacement is deliberate, not automatic synchronization. Review before committing; commit/push only when requested.
